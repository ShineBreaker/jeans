# 引入 guix refresh 改造自动更新工作流

## 决策结论（已与用户确认）

- **工具分工**：分层并存。guix refresh 当主力（GitHub release 包 + rust-crates + git-fetch 有 tag 包 + 改造后的无 tag 包），Python 脚本退化为兜底（只处理 guix 力不能及的非 GitHub 源）。
- **3 个无 tag 包**（winapps/orchis-kde-themes/colloid-kde-themes）：改造为 `with-latest-git-commit` 模式。
- **特殊规则**（tag_prefix/pre-release）：迁移到包定义 `properties`，从 config.json 移除。
- **CI 结构**：保持 auto-update.yml 单 job 串行架构。

---

## 第 1 步：改造 3 个无 tag 固定 commit 包（theme.scm + tools.scm）

按 `amber-pm`（tools.scm:491）的现成模板，给这 3 个包套上 `let` + `git-version` + `with-latest-git-commit` property。

**theme.scm:176 orchis-kde-themes** 改为：
```scheme
(define-public orchis-kde-themes
  (let ((commit "b2a96919eee40264e79db402b915f926436100ad")
        (revision "0"))
    (package
      (name "orchis-kde-themes")
      (version (git-version "2025-10-18" revision commit))
      (source
       (origin
         (method git-fetch)
         (uri (git-reference
               (url "https://github.com/vinceliuice/Orchis-kde")
               (commit commit)))      ; 改：引用 let 的 commit
         (file-name (git-file-name name version))
         (sha256 (base32 "..."))))     ; hash 不变（commit 没变）
      ...                              ; 其余字段不动
      (properties `((with-latest-git-commit . #t)))
      (license ...))))
```

**theme.scm:209 colloid-kde-themes**：同样模式，base 用 `"2025-07-06"`。

**tools.scm:38 winapps**：同样模式，base 用 `"0"`，保留现有 `(patches ...)`。version 会从 `"0-unstable-2026-07-15"` 变为 `"0.0.7f6b6ab"`。

注意事项：
- 这 3 个包的 commit 值没变，所以 sha256 不需要重算（git-fetch 的 hash 取决于 commit 内容，与 version 字符串无关）。
- `revision` 初值统一用 `"0"`。
- 3 个文件顶部确认已有 `#:use-module (guix git-download)`（theme.scm、tools.scm 都用 git-fetch，必然已导入）。

## 第 2 步：给 GitHub release 包加 properties（agent.scm）

把 config.json 里的 tag_prefix 和 check_pre_release 规则，翻译成包内联 properties：

| 包 | 当前 config.json 规则 | 迁移后的 properties |
|---|---|---|
| reasonix-bin | tag_prefix `v` | `((release-tag-prefix . "^v"))` |
| reasonix-desktop-bin | tag_prefix `desktop-v` | `((release-tag-prefix . "^desktop-v"))` |
| open-interpreter-bin | tag_prefix `rust-v` | `((release-tag-prefix . "^rust-v"))` |
| emacs-ellsp | check_pre_release | `((accept-pre-releases . #t))` |
| ellsp-bin | check_pre_release | `((accept-pre-releases . #t))` |

在 agent.scm / emacs-xyz.scm 对应包定义的 `(license ...)` 前（即最后一个字段）插入 `(properties '(...))` 行。

注意：`release-tag-prefix` 的值是**正则表达式**，所以 `v` 前缀写成 `"^v"`（anchored）更精确。

## 第 3 步：修改 test_updated_packages.py 接受合并的更新集合

当前它只读 `report.json`（Python 脚本产出）。改造后 refresh 也更新包，这些包不在 report.json 里。需要让它接受 refresh 的更新列表。

方案：在 `report.json` 之外增加一个 `refresh-updates.json`（CI 步骤产出），test 脚本读取两个文件合并去重。

修改 `select_updated_packages`：
```python
def load_refresh_updates() -> List[Dict[str, Any]]:
    path = Path(__file__).parent / "refresh-updates.json"
    if not path.exists():
        return []
    data = json.load(open(path))
    return [{"name": p, "status": "updated", "old_version": "?", "new_version": "?"}
            for p in data.get("packages", [])]

# main() 中：
packages = select_updated_packages(report)
seen = {p["name"] for p in packages}
for p in load_refresh_updates():
    if p["name"] not in seen:
        packages.append(p)
```

## 第 4 步：改造 auto-update.yml（核心）

**4.1 调整步骤顺序**：把 Guix 安装、nonguix checkout、`/etc/gitconfig` 清理全部**提前到 Python updater 之前**，去掉 `if: has_changes` 条件（因为 refresh 需要先跑才知道有没有变更）。

**4.2 新增 "Run guix refresh" 步骤**（在 Python updater 之前）：
```yaml
- name: Run guix refresh
  shell: bash
  env:
    GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
    GUIX_GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}  # guix refresh 专用变量名
  run: |
    set +e
    . /var/guix/current/etc/profile 2>/dev/null || true
    . "$HOME/.config/guix/current/etc/profile" 2>/dev/null || true
    # 1) GitHub release + git-fetch 包（排除 Python 专属包）
    guix refresh -L modules -L /tmp/nonguix -u \
      crush-bin opencode-bin mimicode-bin orca-ide-bin oh-my-pi-bin \
      codewhale-bin reasonix-bin reasonix-desktop-bin github-copilot \
      ellsp-bin eask-bin neomacs-bin motrix-next-bin cc-switch-bin \
      font-maple-font-nf-cn font-nerd-symbols font-nerd-font-iosevka \
      lr2oraja-endlessdream-bin osu-lazer-bin zen-browser-bin \
      emacs-ghostel emacs-msgu emacs-ellsp colloid-gtk-theme \
      vimix-gtk-themes vimix-kvantum-themes \
      winapps orchis-kde-themes colloid-kde-themes amber-pm \
      nix-ld opentabletdriver-udev-rules waypaper \
      git-credential-keepassxc python-screeninfo \
      2>&1 | tee /tmp/refresh.log
    # 2) rust-crates（crate updater + 递归依赖更新）
    guix refresh -L modules -L /tmp/nonguix -t crate -u \
      $(grep -oP 'rust-\S+' modules/jeans/packages/rust-crates.scm | sort -u) \
      2>&1 | tee -a /tmp/refresh.log
    # 记录 refresh 改动的包（从 git diff 提取）
    scripts/check-updates/refresh-changed-packages.sh > scripts/check-updates/refresh-updates.json
```

**关键设计点**：
- `GUIX_GITHUB_TOKEN` 是 guix refresh 读 GitHub API 的专属环境变量名（不是 `GITHUB_TOKEN`），必须单独映射。
- 显式列出包名列表（不用 `-s module:jeans`，因为实测它报模块加载错误，且会包含 `librewolf-nongnu` 等不该 refresh 的包）。
- **不交给 refresh 的包**（留给 Python）：`zcode`（z.ai CDN）、`font-misans`（无 version URL）、`kimi-code-bin`（npm scoped tag）、`jdtls-bin`（Eclipse + 日期戳）、`librewolf-nongnu`（inherit）。
- rust-crates 单独用 `-t crate`，因为它的包定义结构不同（crate-source 而非 package）。

**4.3 新增辅助脚本** `scripts/check-updates/refresh-changed-packages.sh`：
```bash
#!/bin/sh
# 从 git diff 提取 refresh 改动的包名，输出 JSON
echo -n '{"packages": ['
first=1
for f in $(git diff --name-only -- modules/jeans/packages/); do
  case "$f" in *rust-crates.scm) continue;; esac
  grep -oP 'define-public \K\S+' "$f" | while read pkg; do
    [ $first -eq 0 ] && echo -n ', '
    echo -n "\"$pkg\""
    first=0
  done
done
echo ']}'
```

**4.4 保持 Python updater 步骤**（在 refresh 之后跑），它会看到已被 refresh 改过的包并标为 uptodate，只对它专属的包（zcode 等）产生 updated 记录。这一步的 report.json 与 refresh-updates.json 合并后给构建测试。

## 验证策略

1. **改造后单包验证**：对 3 个改造包跑 `guix refresh -L modules -L /tmp/nonguix --dry-run <pkg>`，确认 generic-git/latest-git-commit updater 能识别（dry-run 不改文件）。
2. **properties 验证**：对加了 release-tag-prefix 的包跑 `guix refresh --dry-run reasonix-bin`，确认它匹配到正确的 tag 系列。
3. **CI 实跑**：手动触发 workflow_dispatch，观察 refresh 步骤日志、refresh-updates.json 产出、合并后的构建测试是否覆盖所有更新包。
4. **回归**：确认非 GitHub 源包（zcode 等）仍由 Python 正常更新。

## 风险与权衡

- **匿名 rate limit**：CI 有 `GITHUB_TOKEN`，本地 `blue upgrade` 若无 token，refresh 对 GitHub 包会受限。这是可接受的——CI 是主要执行点。
- **properties 正则写错**：`release-tag-prefix` 是正则，写错会导致 refresh 找不到 tag。dry-run 验证可捕获。
- **rust-crates 递归更新**：`-t crate` 可能拉入大量传递依赖更新，首次跑可能改动巨大。可先 dry-run 评估规模再决定是否首次手动处理。
- **包名列表维护**：显式列包名意味着新增包要手动加入 refresh 列表。可接受——比 `-s module:` 的副作用更可控。
